# evfleet — driver onboarding

The onboarding funnel: candidates apply, are grouped into cohorts, and are matched to financing institutions. Despite the name it is **not** fleet management.

**Stack:** TanStack Start (React 19, SSR) · Vite · Tailwind · Supabase.
Originally generated by Lovable, now also deployable as a container.

---

## Running it locally

```bash
npm ci
cp .env.example .env      # then fill in the two Supabase keys
npm run dev
```

Get the keys from the Supabase dashboard → Project → Settings → API.
**This project's Supabase ref is `qrgdysaojytfaaurfjkr`.**

```bash
npm run build             # production build
npm run preview           # serve that build
npm run lint
```

## The two rules specific to this stack

**1 · `VITE_*` is compiled in, everything else is read at run time.**
Vite inlines anything prefixed `VITE_` into the client bundle **at build time**. Changing one
needs a **rebuild**, not a restart. The service-role key is deliberately *not* prefixed, is
read only in `client.server.ts`, and must never become a build arg — build args are recorded in
image history and travel with the image.

**2 · Do not add Vite plugins by hand.**
`vite.config.ts` uses `@lovable.dev/vite-tanstack-config`, which already includes TanStack
Start, React, Tailwind, tsconfig paths, Nitro and env injection. Adding any of them again
breaks the build with a duplicate-plugin error.

## Deployment

The `Dockerfile` builds a self-contained Node server (`.output/server/index.mjs`, ~237MB) by
setting `NITRO_PRESET=node_server` at build time — the default preset is `cloudflare`, which is
what Lovable deploys to, so **the Lovable path keeps working unchanged.**

```bash
docker build -t uza-evfleet:latest   --build-arg VITE_SUPABASE_URL=...   --build-arg VITE_SUPABASE_PUBLISHABLE_KEY=... .
```

Whole-estate deployment: `00-group/deploy/` in the `UZA-SOLUTIONS-GUIDE` repository.

## What matters most in this repository

**The highest-priority change in this repository, and it has a deadline.**

Add a structured field at intake recording **which published lender eligibility condition each
candidate fails** — no registered business, no 12-month trading history, no fleet-app
integration, no bank settlement record, no tracker.

Those conditions are published by BK and I&M. Recording which ones a candidate lacks turns
UZA's central claim — *we reach people the market cannot* — from an assertion into arithmetic
against a public standard.

**It can only be captured at intake.** Ask somebody in December which conditions they failed in
September and you get a memory, not a record.
